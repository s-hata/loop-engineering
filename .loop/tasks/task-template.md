## Task

`対象ディレクトリまたはコンポーネント/` に、`達成したい成果` を実装する。

実装対象を、別のエージェントが追加の前提確認なしに着手できる粒度で記述する。
必要に応じて、対象ファイル、利用する既存の仕組み、参照すべき設計資料を明記する。

### Scope

- 対象: `今回変更する範囲`
- 対象外: `今回変更しない範囲`

### References

- `設計書・仕様書・既存実装へのリンク（不要なら削除）`

### Expected structure（任意）

```text
対象ディレクトリ/
├── 追加または変更するファイル
└── 関連する設定・テスト
```

## Acceptance criteria

- `実装後に確認できる成果` が存在する。
- `利用者・後続処理・外部インターフェースから観測できる振る舞い` を満たす。
- `必要な設定、依存関係、テスト、ドキュメント` が対象範囲に応じて整備されている。
- `test_command` に記載した検証コマンドが成功する。

受け入れ条件は実装方法ではなく、レビューで確認できる結果として記述する。
コマンドの成功だけでは確認できない画面表示、配置、互換性、運用上の条件も必要に応じて明記する。

## Constraints

- 変更範囲は `対象範囲` に限定し、`対象外の範囲` は変更しない。
- 既存の `互換性・技術スタック・バージョン方針・データ形式` に従う。
- 既存の公開インターフェースやデータを変更する場合は、互換性の扱いを明記する。
- 認証情報、トークン、環境固有の秘密情報をリポジトリへ追加しない。
- `その他の安全性・性能・運用上の制約（不要なら削除）`

## Verification notes

`test_command` には、対象リポジトリで再現可能な決定的検証コマンドだけを記載する。
依存関係のインストール、Lint、フォーマットチェック、テスト、ビルドなどを必要な順序で指定する。
検証コマンドで確認できない項目は、ここに手動確認やレビュー観点として記載する。

- 自動検証: `test_command` の結果を確認する。
- 手動確認: `画面、ログ、ファイル構成、移行結果などの確認内容（不要なら削除）`
- 注意事項: `環境依存の確認方法や既知の制約（不要なら削除）`
